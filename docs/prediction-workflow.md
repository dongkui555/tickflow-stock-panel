# 盘后预测与企业微信通知

短线AI荐股页新增“盘后预测 / 次日执行”。自动预测与通知可分别关闭。

## 执行规则

- 交易日19点后每5分钟检查调度机会。数据校验或预测失败后间隔30分钟再查。
- 核心数据未齐时主动增量补差：当天缺失日K、核心指数、主力资金；技术特征从最多121个本地日K分区重算当天，不改写历史日期。
  与盘后同步共用分项检查点；重试间隔依次为5、15、30、60、120分钟，此后每120分钟继续尝试。
  已有分项冷却时间优先遵守，失败五次后显示需关注但不会静默放弃。重启保留次数与冷却状态。
  自动补差仅在交易日19点后的预测窗口运行，不自动全量下载历史或分钟K；首次历史基线缺失需先完成首次同步。
  每轮补差后重新按实际数据日期、有效字段与覆盖校验，API返回成功或任务完成不能代替校验。
  上游无权限、无数据或网络故障无法保证补齐；此时继续等待且不生成/发送正式预测。
- 与已有同步共用执行槽，不并发读取正在改写的日线。长任务占用时等待释放。
- 校验当天日K、成交量/额、技术特征、资金字段、核心指数。
  全市场日K数量至少达到最近一日有效数量的98%；特征和资金各覆盖当天有效股票的98%。
  停牌零成交不作为可交易候选；每只入选股票必须同时拥有有效日K、特征和资金。
  该门槛是覆盖检查，不等于证明所有行情没有跨来源或复权错误。
- 数据就绪后使用已有模型重新推理，不自动训练、不提交真实或模拟订单。
- 留档包含候选、收益预测、模型元数据、市场环境、输入版本与生成时间。
  同日输入文件发生变化时生成新版本，保留旧记录，不覆盖历史预测。
- 次交易日上午8点至10点复核海外风险和本地带发布时间的隔夜新闻。
  缺失或过期、候选不是最近交易日生成、或命中保守风险关键词时只观察。
  关键词检查不是完整公告审计；无新新闻记录也按待确认处理。
- 盘中推荐只使用留档候选和模型预测。继续执行现有分钟量价确认、市场闸门和仓位约束。
  无快照、无当天盘前复核、非交易时段时新开仓仓位为0；旧研究候选可以显示但不能确认买入。

## 企业微信

使用现有企业微信智能机器人的 BotID/Secret 长连接，通过 `aibot_send_msg` 主动发送 Markdown。
预测通知不再使用群 Webhook，也不会在智能机器人离线时切换到其他收件通道。
用户要求发到自己的单聊：上线后先向智能机器人发送一条单聊消息，再在荐股中心的“单聊接收用户”选择自己的 UserID。
只记录会话标识、类型和最近收到时间，不保存消息正文、不自动订阅任何收到过消息的人或群。
接收用户与当前 BotID 绑定，更换机器人后需重新确认；API 拒绝未识别的用户和群会话。
协议依据：[企业微信官方 SDK](https://github.com/WecomTeam/aibot-node-sdk)，复用现有连接，不另建第二条长连接。

每个候选版本发送一条摘要（前5只及预测日期），完整名单在页面留档中查看。
只有匹配请求ID且 errcode 为数字0的成功回执才标记已发送。明确失败最多尝试3次，间隔30分钟。
连接未就绪或接收用户未绑定时等待，不虚报已发送；回执超时或发送中断视为结果不确定，需人工核验，不自动重复发送。
进程在发送途中中断会保留“发送中或回执待核验”，不自动重发该不确定结果，避免刷屏。
网络超时仍有远端已收但回执丢失的可能，因此不承诺外部系统恰好投递一次。平台权限、消息配额和接收目标有效性以企微回执为准。
预测完成和通知发送前再次核对当天数据版本；变化时等待重算，旧日期预测不跨日补发。

## 状态与兼容

状态接口：`GET /api/short-term-ai/workflow`。
开关接口：`POST /api/short-term-ai/workflow/config`，参数为 `enabled`、`notify`。
记录位于数据目录下 `user_data/prediction_workflow/`；`snapshots/` 保留各版候选。
关闭自动预测后恢复原来的实时聚合研究流程；指定历史日期的研究不使用当前工作流闸门。
新增候选仍需样本外验证，通知不构成买入指令。
