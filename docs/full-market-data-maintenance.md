# 全市场数据维护

## 日常自动任务

- 使用系统原生调度器，不依赖网页一直打开。Docker 服务必须运行。
- 盘前、午盘保留原设置；盘后默认北京时间 15:30，分钟范围强制为全市场，不沿用盘中自选/模型 Top 股票池。
- 日常仅补最新缺口、近期不完整分钟和公告更新，不每日重新下载两年历史。空库或长时间停机后的大缺口需要显式初始化/修复。
- 分钟增量按股票自己的时间戳续传；收盘后最多请求至 15:00，同时检查完整的 240 个常规分钟，不能只看最后一条时间。
- 对近期已收盘的分钟缺口，入库前核对日K价格、量额和已有分钟；冲突保留原记录，合格新增记录入库前备份。盘中未完成的分钟可以继续更新。
- 财务按公告日期做全市场批量增量，股本使用全市场 daily_basic 批次；批量失败不能退化为几千只股票逐股请求。
- 扩展数据包括已接入的资金、竞价、龙虎榜、板块等。新闻按实际接口可用性更新，不能由近期 RSS 推导出两年历史。

## 忙碌和失败

- 盘后排队状态写入 `data/user_data/after_close_sync.json`，重启可恢复。
- 每 5 分钟检查执行槽；被其他数据任务占用不消耗尝试次数。
- 实际执行失败后等待 15 分钟，最多尝试 3 次。各数据源的权限、空返回、超时及未通过校验都必须显式保留为未完成。
- 延迟任务只在确认的交易日、设定的盘后时间之后执行；旧任务超过 3 天会过期，不挤占早盘。
- 不覆盖 API 权限限制，不使用合成值冒充真实行情，也不以单个数据源的最新日期代表全库完整。

### 集合竞价分项补查

- 竞价分项补查与上面的整批任务重试独立。最近 3 个日K交易日、最多回看 7 个自然日，只请求缺失股票日；通常间隔 30 分钟，连续 8 次无进展后保留 `needs_attention`，但改为每 3 小时低频补查，不再永久停止。执行槽忙碌时仍不启动第二个任务。
- `close_data_sync.json` 增加 `data_state`（整日空、部分覆盖、完整）、`error_reason` 和脱敏的 `error_message`。成功响应但空表不证明接口有权限，也不证明当天无成交；少量缺股不等于整日同步失败。未核实的股票不会自动排除或填零。
- Tushare 插件 `get_auction(..., strict=True)` 用于单日分项补差，将空响应、缺失股票、超时和错误日期向调用方报告；默认历史批量调用仍保持已有兼容行为。错误信息不记录原始带凭据 URL。
- 当前历史竞价口径仍为 [`stk_auction_o` 的 9:30 数据](https://tushare.pro/document/2?doc_id=353)。[`stk_auction` 开盘竞价成交快照](https://tushare.pro/document/2?doc_id=369)是不同接口，包含股票及 ETF；即使后者能返回数据，也不直接写成前者、补造高低价，或悄悄替换模型使用的成交量与成交额。快照接入须独立标明来源和口径，并验证模型特征兼容性。

## 运维入口

- `GET /api/pipeline/after-close-status`：时间、全市场范围、重试规则与最近状态。
- `POST /api/pipeline/repair-market`：指定已结束的历史起止日期、数据类型和请求预算，仅补缺失日期及检测到的稀疏日K分区。
- 修复任务采用已有 JobStore 与执行槽；进度仍在数据任务列表查看。接口返回 `reused=true` 代表复用了当前任务，没有重复启动。
- 部分写入成功但仍有缺口时，任务状态为失败/部分完成，详细原因在 `data/import_reports/market_repair_*/summary.json`，已完成的数据保留。
- 分钟补差失败的股票日自动进入第三方交叉核验：Promax/Tushare 与东方财富日K分别核对本地日K和分钟汇总。网络超时、限流、连接断开与网关准备中标记为 `source_unavailable` 并退避，成功但无该日记录才标记为 `source_no_record`。
- 交叉核验结果写入 `data/import_reports/cross_source_verify/<run_id>/`，包括 `report.json`、`details.csv` 和 `retry_queue.jsonl`；`daily_baseline_repair_candidate`、`qmt_turnover_conflict`、`quarantine` 不会被当成普通完整数据。
- `use_local_minutes=true` 仅适用于 `datasets=["daily"]`，严格完整分钟可聚合缺失日K，标记 `data_source=local_minute_aggregate`，保留所有已有日K。聚合数据不是独立日线源校验。
- 需要重新计算派生指标时显式设置 `rebuild_enriched=true`，不会因此重新拉取所有行情。

## 全库审计

`scripts/audit_market_data.py` 检查日K、资金、竞价、财务、扩展、新闻和海外 SQLite；`scripts/audit_minute_integrity.py` 检查分钟文件、时点、价格、量额和日线交叉一致性。

`scripts/finalize_market_audit.py` 输出按股票日、月份和数据类型拆分的缺口清单，并复核日K补数没有改变备份中的旧记录。`scripts/probe_minute_gaps.py` 只读抽样验证 API 历史缺口，不自动覆盖。`scripts/repair_market_duplicates.py` 仅处理白名单日汇总表完全相同的重复记录，写前备份并读回验证，不去重可能代表不同真实成交的大宗交易事件。

日期覆盖、文件可读、价格量额合法、来源间一致是不同的检验层次。复权、证券代码变更、退市与停牌等差异要单独核实。训练和回测不能只凭“分区都存在”认定数据可靠。

## 北交所盘后成交口径

北交所大宗交易在盘后计入全日成交量、成交额，不属于常规分钟成交。日K总量与常规分钟合计不能直接混比，规则依据见[北交所交易制度解读](https://www.bse.cn/uploads/6/file/public/202111/20211119182131_imqohh30d0.pdf)。

经独立日线和逐笔大宗交易记录核实的旁证，存放于 `data/minute_reference_evidence/date=YYYY-MM-DD/六位代码.json`。版本1记录原日K快照、明确的股/手单位、独立全日总量、标准化大宗交易及来源摘要哈希。校验时才计算常规时段参考量额，不覆盖原日K，也不从分钟差额反推所谓大宗交易。

补缺、分钟研究读取、定时同步验证和审计工具共享该口径；调用 `daily_reference` 时需传入 `data_dir`。旁证与股票、日期、原日K不符，或金额、数量非法时，该股票日不放行。旁证不会自动创建，也不能证明来源完整；须先核验独立原始记录，保留原始响应。新增旁证和分钟替换必须遵守备份、授权及回读流程。
