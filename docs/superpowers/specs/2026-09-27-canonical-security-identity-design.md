# 统一证券身份与历史数据迁移设计

日期：2026-09-27

状态：用户已于 2026-09-27 确认设计并要求执行；实现计划待评审。本文不代表代码已修改、数据已迁移或已部署。

## 1. 目标与边界

用户已确认：维表使用 `代码.市场`；日K、分钟K、资金、竞价、财务、新闻的证券关联统一采用完整身份；补差键使用 `资产类型|市场|代码|日期`；历史数据先备份分批迁移；股票、指数、ETF 分开解析，不能只凭六位代码猜市场。

本次属于 L3 核心契约迁移，涉及提供方、仓库、校验、任务、模型、API 和前端。不新建第二套业务系统，不调整交易策略，不借迁移修改 OHLC、成交量、成交额、复权口径或历史预测成绩。

成功标准：切换后的活动数据、读写关联、任务、缓存、API 中只存在一种证券身份标准；原格式仅保存在只读备份、原始供应商载荷和不可变历史审计中，不参与业务 join 或去重。

## 3. 方案选择

1. 只在界面补后缀：改动少，但存储和 join 仍有歧义，不满足本次需求。
2. 全仓字符串替换并原地覆盖：速度快，但会误改指数、历史更名、新闻和授权范围，无法接受。
3. **统一契约，离线分批迁移，验收后整体切换**：推荐方案。先完成所有活跃读写路径与测试；暂停写入，逐分区备份与迁移；验收通过后才恢复生产。活动系统不双写两种格式。

旧格式只由专用迁移解析器或显式用户输入解析接口接收，不在活动仓库查询中永久保留“裸代码兜底”。

## 4. 标准身份契约

### 4.1 字段与键

```text
asset_type   stock | index | etf
exchange     SH | SZ | BJ
code         000001
symbol       000001.SZ
security_key stock|SZ|000001
stock_day_key stock|SZ|000001|2026-09-24
```

`code` 可以作为独立展示字段或供应商参数存在，但禁止单独用于业务关联、缓存、去重、覆盖和授权。`symbol` 必须始终是完整格式，并与 asset_type、exchange、code 一致。

证券身份以结构化字段为准，序列化键由统一函数生成。数据库使用结构化复合唯一约束，同时提供稳定的 stock_day_key；不依赖四处拼接字符串。

证券身份与记录主键不是同一个概念：

| 数据集 | 记录唯一性 |
| --- | --- |
| 维表 | security_key；历史维表额外包含有效区间 |
| 日K | security_key + 交易日 + 价格口径（如该表存多口径） |
| 分钟K | security_key + 北京时间分钟戳 + 周期 |
| 资金/竞价 | security_key + 日期/时间 + 数据集及必要细分字段，保留来源证据 |
| 财务 | security_key + 报表类型 + 报告期 + 公告/修订版本，不把同日不同报告合并 |
| 新闻 | 新闻自身 id；关联表为 news_id + security_key，多证券关系保留 |
| 分钟补差 | asset_type + exchange + code + trade_date，即 stock_day_key；周期若扩展则独立任务类型 |

例如 `stock|SZ|000001` 和 `index|SH|000001` 必须独立。即使数值代码相同，也不能合并或共享缓存。

### 4.2 身份解析与历史映射

解析依据是显式资产类型、按日期有效的证券维表、来源返回的交易所，以及已有更名/换码证据。对请求身份、源返回身份、目标身份三方交叉核对。

- 活跃业务接口要求完整 symbol 和确定的资产类型。输入缺失或矛盾返回明确错误。
- 用户搜索可输入裸代码，但必须查证券维表，唯一命中才返回完整身份；多个命中展示选择，不默认归深市。
- 历史裸代码只有在所属数据集明确资产类型、目标日期存在唯一身份依据时才能迁移。
- 代码前缀只可用于提示明显异常，不能独立生成交易所或覆盖维表证据。
- 名称变更不改变证券身份；代码/市场变更使用有效起止日期及 predecessor/successor 映射，保留原始来源身份，不把所有历史强制改成最新代码。
- 北交所旧代码与 `92xxxx` 只按有依据的映射解析。供应商使用最新代码回溯历史的情况需来源映射证据，不推断退市或上市时间。
- 未上市、退市、历史停牌和交易所休市继续作为独立状态；身份迁移不意味着该日应有240根分钟。
- 无法唯一解析的记录进入隔离清单，保留原文、日期、来源和原因，不写入活动规范表，不算完整数据。

### 4.3 新闻和海外数据

宏观新闻、行业新闻可能没有个股关联，保留新闻主记录和空关联集合，不强行配股票。关联身份未知只隔离该关联，不丢弃新闻正文。

当前系统已有海外 ticker，禁止将 AAPL 等按六位A股规则转换，也不能强加 SH/SZ/BJ。海外证券关联按其自身交易所元数据解析；无法确认时保留在原始载荷/待核验关联中。此项不是新增海外行情业务。

## 5. 读写与应用改造

复用现有 security_identity 模块建立唯一解析入口。提供方负责将本源参数和响应转换为标准身份，service 和 repository 只收规范身份。所有写入路径必须经过身份门禁，包括手工导入、QMT DAT、StockDB、Tushare、TDX、离线脚本和定时同步。

仓库、校验、策略、训练、选股、监控、模拟仓和前端必须同时改为完整身份关联；删除承担身份关联职责的 `_code`、正则截取六位、split 去市场后缀、默认 stock/SZ 等路径。供应商参数格式转换及纯展示 code 不在删除范围内。

缓存键包含资产类型、symbol、必要日期/周期和身份 schema 版本。切换时只失效相关缓存、刷新 DuckDB 视图和前端查询；不因改 symbol 默认重算全历史技术指标。

已发布预测、历史通知、报告及既有模型文件不原地改写。保留旧产物及其数据版本，建立旁路身份映射供读取展示；新产物使用新契约。模型兼容性检查未通过时禁用该模型的新预测，而不是静默替换特征或重写旧成绩。

## 6. 补差与授权迁移

队列表新增 asset_type、exchange、code、canonical symbol 和 stock_day_key，唯一约束使用完整身份和日期；不清空队列伪装修复。

- 只变身份字段，不把 retry 改成 complete，不重新生成不存在的缺口。
- 迁移保留 attempts、next_retry_at、source_chain、原任务 id、原因和历史事件。
- 旧键映射到同一新键时先核对状态和证据。矛盾状态进入待核验，不能简单取“完成”或取最后一条。
- 授权迁移保存原 task/scope、source、operation、证券日期和授权审计；同范围授权继续有效，不扩大到新源或新操作。
- 原 scope/hash 如由旧符号生成，保存明确的旧新 scope 映射，而不是重算后丢失授权。
- 替换行情的备份要求不变；迁移身份字段不是对所有量价冲突的新覆盖授权。

## 7. 历史迁移与发布

### 7.1 只读预检

生成带版本的清单，覆盖所有活跃数据集、SQLite、JSON 任务/配置和派生数据引用。记录文件校验和、schema、行数、大小、代码格式分布、映射成功/歧义/重复/冲突数量及预计备份和临时空间。

没有身份字段的数据集不做强行格式转换；原始证据、备份和不可变研究产物列入免改清单。日K缺口统计不能以当前5000股维表代替完整历史证券池。

### 7.2 停写和备份

正式迁移前启用维护锁，暂停全部数据写入者，包括定时任务、分钟补差、实时落盘、训练和外部导入 worker。只停 HTTP 服务不足以视为停写成功。获得独占迁移锁后才继续。

按“维表/历史映射 -> 日K和复权 -> 分钟K -> 资金/竞价/财务/新闻关联 -> 派生引用/用户状态 -> 队列/授权”的依赖顺序迁移。

每个批次先复制完整原文件并校验 SHA-256，再写临时新文件。SQLite 使用一致性 backup 和事务迁移，不复制可能未 checkpoint 的主文件来冒充完整备份。备份与原目录分离、不可被应用 glob 扫描。

备份默认置于当前工作区数据目录下专用 migration_backups；预检确认空间不足则停止，不删除用户历史数据。若需要换盘，先明确备份目标，再执行。

### 7.3 分批、恢复与切换

按数据集及交易日分批，维护每文件 journal：原校验和、备份路径、映射版本、转换后校验和、验证结果、发布状态。单个文件临时写入验收后原子替换，应用在整个迁移期保持维护状态，不能读到半套格式。

重复执行时仅续处理未完成批次；已完成文件必须与 journal 校验和一致。输入发生变化则停止该批次，不覆盖新写入。任何失败均保持旧版本可回滚且不宣布迁移完成。

所有批次验收完成后发布统一 identity_schema_version。生产应用启动必须核对代码和数据版本，拒绝旧 writer 写入新格式。恢复任务前做读写冒烟和只读覆盖审计，再按真实缺口恢复补差。

回滚保持停写：按 journal 恢复一致的文件、SQLite、配置和匹配的旧代码版本。切换后新增数据先单独保留，不能通过回滚无声丢失。备份保留，清理另行授权。

## 8. 验证与完成门槛

1. 身份测试覆盖同数值代码跨市场/资产、未知身份、显式后缀冲突、大小写、错误输入和海外 ticker，不默认补市场。
2. 历史测试覆盖上市前、退市后、停复牌、换代码有效期、北交所历史映射及供应商历史回溯代码。
3. Provider、同步和导入契约测试验证新写入必为规范身份；来源不一致不入库。
4. 迁移测试覆盖重跑幂等、断点恢复、空间不足、备份失败、并发写入、重复键、隔离和完整回滚。
5. 所有业务记录核对迁移前后非身份字段不变；数量满足“原记录 = 活动记录 + 有凭据去重记录 + 隔离记录”，不静默丢行。
6. 完整分钟和已验证QMT稀疏日仍按原规则判定；标准化本身不能改变合格率或解除量价冲突。
7. 队列/授权测试证明原批准范围持续有效、未批准冲突仍拦截、重启不重复执行已完成工作。
8. 后端受影响测试、前端构建及个股/指数/ETF查询、K线、自选、模拟仓、资金、财务、新闻、训练、回测、通知冒烟全部通过。
9. 全量活动证券字段不再有裸 symbol 或错误后缀；代码扫描命中的六位提取必须逐项归为供应商参数/展示或消除，不能仅靠搜索次数宣布完成。
10. 可观测输出明确区分：已规范化、已备份、隔离待核验、重名去重、未迁移、回滚。隔离不算缺口已补齐。
