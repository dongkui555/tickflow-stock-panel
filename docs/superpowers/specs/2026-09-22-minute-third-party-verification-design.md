# 分钟数据第三方核验流设计

## 目标

把分钟数据导入后的第三方核验固化为现有盘后维护链路的一部分。以后 QMT、Promax、TDX、StockDB 或离线包导入失败时，系统自动按“股票+交易日”调用可用的第三方日K源进行裁决，区分数据错误、成交口径冲突、源不可达和源无覆盖，不再依赖临时脚本或人工猜测。

## 范围与约束

- 核验是导入后的独立阶段，不改变现有分钟源的身份校验、时间轴校验和备份替换规则。
- 第三方日K只用于验证分钟汇总，不用于合成分钟K。
- 不把网络超时、限流、断开和网关准备中当作“无数据”。
- 只有证券身份、分钟时间轴、OHLC、成交量和成交额满足对应合同，才允许进入标准分钟表。
- 自动修正日K必须至少有两个独立来源与新分钟汇总一致；否则只产生候选，不覆盖本地日K。
- 价格路径通过但成交口径未通过的数据可以作为隔离证据供技术指标诊断，但不能进入资金特征或高置信度模型训练。
- 已发布预测快照不因后续核验结果被改写。

## 核验流

```text
导入源数据
  -> 本地身份/时间轴/OHLCV校验
  -> 失败股票日进入 cross-source-verify 队列
  -> Promax/Tushare 日K
  -> 东方财富日K
  -> 本地已验证日K或离线日K
  -> 证据裁决
  -> 导入候选 / 日K修正候选 / 换源重试 / 隔离
```

核验顺序由配置决定，默认使用 `promax_daily -> eastmoney_daily -> offline_daily`。每个源都必须返回标准字段：`symbol`、`date`、`open`、`high`、`low`、`close`、`volume`、`amount`，并携带来源、请求时间、单位和错误类别。

## 裁决状态

| 状态 | 判定 | 后续动作 |
| --- | --- | --- |
| `minute_import_candidate` | 分钟汇总与本地日K及至少一个独立日K源一致 | 允许按现有导入器入标准分钟表 |
| `daily_baseline_repair_candidate` | 分钟汇总与两个独立日K源一致，但本地日K不一致 | 先备份，生成日K修正候选；默认不自动覆盖 |
| `qmt_turnover_conflict` | 本地日K与独立日K一致，但分钟源成交量/额不一致 | 拒绝该分钟源，按分钟备源链重试 |
| `existing_values_conflict` | 新数据与本地已有记录冲突 | 仅在用户已授权且新数据独立校验通过时备份替换 |
| `source_no_record` | 请求成功且源明确返回没有该交易日记录 | 记录源不覆盖，不再对同一源无限重试 |
| `source_unavailable` | 超时、限流、5xx、连接断开或网关准备中 | 指数退避，保留原始失败证据 |
| `quarantine` | 三方量价或身份都无法形成一致结论 | 不入库、不训练资金特征，等待人工或离线包 |

## 持久化

在 `data/import_reports/cross_source_verify/<run_id>/` 保存：

- `report.json`：批次汇总、源状态、裁决数量、下一次重试时间；
- `details.csv`：每个股票日的身份、分钟行数、三方OHLCV、单位、误差、裁决和证据；
- `retry_queue.jsonl`：只保存可重试项，包含 `next_retry_at`、`attempts` 和退避原因。

队列状态与 `minute_gap_queue` 通过完整股票身份键关联，禁止只按六位代码合并 SH、SZ、BJ、指数或ETF。

## 与现有模块的连接

- `backend/app/services/minute_repair.py`：导入和现有量价合同保持不变，输出标准失败原因。
- 新增 `backend/app/services/minute_cross_source.py`：实现第三方日K适配、标准化、有限重试和裁决，不直接写生产数据。
- `backend/app/services/daily_maintenance.py`：分钟任务完成后调用核验编排；只把裁决结果写回缺口队列。
- `backend/app/services/minute_gap_queue.py`：增加核验中的状态和下一次重试时间，避免同一股票日重复请求。
- `backend/app/services/minute_failover.py`：复用现有源冷却和错误分类，不重复实现退避算法。
- `backend/tests/`：覆盖源成功、空记录、网络错误、两源一致、三方冲突、身份冲突和重试冷却。

## 失败和安全策略

- 第三方源不可达时，核验结果为 `source_unavailable`，不是 `source_no_record`。
- 日K源成交量是手、股或未知单位时必须显式转换；未知单位直接隔离。
- 一个源返回错误不能阻塞其他源，也不能清空已有的分钟记录。
- 核验任务只处理失败队列中的股票日，不扫描全历史。
- 日K修正和分钟冲突替换都先写备份，再原子替换并回读验证；失败自动恢复原文件。

## 成功标准

1. 任意分钟导入失败都能自动产生第三方核验记录，不需要临时脚本。
2. 网络失败、源无覆盖、成交口径冲突和真实价格错误在报告中可区分。
3. 同一股票日不会因重复调度重复请求，退避后只重试仍可重试的源。
4. 未通过裁决的数据不会进入标准分钟表、资金特征或高置信度模型训练。
5. 现有 `minute_repair`、`minute_failover`、QMT稀疏239根规则和备份替换测试继续通过。
